## ✨ 功能

- [x] 🎮 **自动演出** — 当前曲目 / 随机选曲，五档难度，连续运行
- [x] 🎹 **单人实时演奏** — TAP、FLICK、HOLD / Slide、双押与 Special 方向音符
- [x] 👥 **协力演出** — 普通房、创建房间并邀请全部好友、接受唯一好友邀请、私人房间号，支持筛歌与同房续演
- [x] ⚔️ **竞演演出** — 按普通协力任务选择和启动，支持活动/自由房型、满员开演及竞演结算；沿用协力的 Profile、停止、生命归零跳车选项与错误恢复流程，无额外实验开关或验收前置。
- [x] 🎼 **Bestdori 本地谱面辅助** — Hard / Expert / Special 谱面提供歌曲结构与时序
- [x] 🔄 **MFA 谱面同步** — 定时增量更新或手动同步，空闲时维护本地曲库
- [x] 🎯 **实时演奏校准** — 一次排练、一次正式验证，生成并选择匹配的 Profile
- [x] 🏆 **挑战演出** — 四档点数、五档难度、连续轮次；生命归零后停止并保留现场
- [x] 🎼 **组曲演奏** — 自由巡演 / 课题巡演，支持断点续跑与逐首结果
- [x] ⏩ **结算容错与可选检查** — 成绩数字结合本局可信谱面总数复核并有界纠错；读取异常保留完成状态，可跳过成绩数字检查
- [x] 🧪 **调试记录** — 轻量 Trace、开场截图或完整记录，关联开演、输入、结算与清理证据
- [x] 📹 **手动流程录像** — 录制界面操作，生成可逐帧定位的 MKV 与首末帧
- [x] 🎁 **交换所抽箱（开发候选）** — 从当前交换所主页面启动，默认预览；可填写最大抽数或活动币预算，两项同时填写取更紧者，每抽10币，精确预算最多10000抽。用户预算无需识别总余额；两项均0才自动读取一次可信初始余额，之后按已确认抽取扣减预算。180／230箱使用无放回超几何有限预算策略，以火罐期望数量为唯一目标；每笔继续实读剩余奖品、火罐与特别礼物，按实际奖池变化重算。执行前要求游戏内“全部交换”和“获得特别礼物时自动停止”均为OFF；确认页数量与费用、提交后的结果页、精确奖池变化全部通过才记录完成，未知结果保留未决账本并停止，不重复消费确认。非消费入口未送达时有界重试。最终提交采用持续800毫秒确认与单次150毫秒同点手势作为输入可靠性保护。当前完整验证2922通过／13跳过，含19例真实画面回放；已通过实际开发MFA在雷电单设备、1280×720、180箱中的跨夜连续验收：30次十连消耗3000活动币，含两次策略换箱，预算归零自然结束、无未决消费。230箱、其他设备及其他网络条件不在本次真机覆盖内；本次不发布新版本。

协力的“创建房间并邀请全部好友”会创建私人房间，从大厅下方发送一次好友邀请，至少一名好友加入后开始选曲；“好友邀请房间”只接受列表中唯一有效的邀请。发送或起房结果不明时停止并保留现场，避免重复发送；同房续演只重新起房，不重复邀请。活动卡片布局同时保留旧版与紧凑入口模板。

双设备开发验证使用 `scripts/run_cooperative_device.py` 的独立运行目录及共享设备租约，各自核对端点、宿主进程、boot ID 和 Android 指纹。`--engine native` 可显式用于雷电和 MuMu；Profile 必须匹配所选引擎。完整流程启动前应分别将游戏内体力消耗设为 0，并确认演奏器已经就绪。

协力与竞演的“跳车”选项默认关闭；开启“生命归零后手动跳车”后停止输入，切回游戏并结束任务，提示“请手动跳车”。关闭时继续演奏及结算。

协力和竞演在开演前遇到成员退出、匹配取消或房间失效时，按已确认页面取消或确认弹窗，再安全重新入房，保留已完成局数，不占用演出失败重试次数；旧的“成员退出即结束”选择不再导致整项任务终止。每次恢复有时间边界，反复成员退出本身不作为任务失败；只有无法安全恢复页面才结束。开演前的“连接失败”双按钮弹窗按正文独立识别，优先重试，必要时取消后安全恢复并重入，不再仅凭通用“错误”标题误当成员退出。演奏中和结算期间不检查通用成员退出标题。

入房时「匹配中」连续可见 12 秒才尝试取消，最多恢复两次，并受本次入房总时间限制；取消无效满 6 秒且新画面仍为匹配弹窗时才发送 BACK。已经入房就直接继续，只有真实房间选择页、目标房型与原确认坐标均有效时才重新确定；未知或黑场只被动等待，私人房间不会借用普通房间坐标。当前候选不含需要 root 的断网跳车功能，已部署开发环境；LIVE BOOST 面板完成零消耗导航验证，协力取消后重新匹配已有同代码真机证据，竞演及匹配恢复的 BACK 分支仍待真机验收。本轮暂停发布新版本。

所有演出任务的体力补充、成绩统计、诊断记录、进度通知及附加报告失败只警告并继续；正在演奏时优先保持输入和必要监测。校准、组曲的附加写盘失败保留本任务内存进度，跨任务续跑仍要求可信保存记录，校准缺失必要成绩不能接受 Profile。人工停止、真实演出失败、身份/Profile/输入完整性失败及无法安全继续的导航故障仍保留明确失败原因。免费抽卡的消费安全确认与手动录制的录像输出属于各自核心功能，失败不会伪报成功。

设置侧栏前两项为“演出设置、谱面更新”。演出设置使用顶部“常用、Profile、流速、Native、任务安全、Legacy、调试目录”标签页；常用提供 Native 总开关和体力消耗，其他选项直接在对应页展开。谱面下载与定时维护位于独立的“设置 → 谱面更新”。

“演出设置 → 常用”的目标体力消耗为 0–3，默认 3。单人、自动、协力、竞演和巡回任务进入演出选择页时核对 LIVE BOOST，不一致则修正，关闭后重开读回复核；无法识别或保存失败会停止任务。测试时选择 0，恢复日常任务前改回 3。挑战点数独立，一键实时和组曲中途续跑不离开现场修改体力；双设备测试脚本仅将隔离副本固定为 0。非零自动切换已完成离线状态机验证，尚待真实游戏复核。

各演出任务分别提供“体力补充（仅主页）”，默认关闭，可选择仅小火罐（+1）、仅大火罐（+10）或大小火罐智能补充。该选项属于当前任务，不在演出设置中；旧全局补充开关和累计上限字段均忽略，不直接改写已有 Profile。目标消耗仍在“演出设置 → 常用”设置，范围 0–3。

补充仅在主页读取真实体力，已足够下一局时不消耗道具；例如已有 17 点、每局消耗 3 点时直接继续。低于下一局需求时，根据剩余次数、大小罐库存与允许类型规划批次，计划补充后的体力不超过 24 点。剩余总需求在 24 点以内时优先一次补够尾段，再减少超量与道具数：每局 3 点、剩 8 局、当前 1 点时，库存允许便用 2 大罐加 3 小罐补至 24 点；只剩 1 局时则用 2 小罐补至 3 点。长任务优先减少后续回主页次数，并避免可规避的只剩一两局还需再补；在相近批次中优先 18–24 点、较少道具，再靠近 20 点。无限任务按这个目标区间选择，允许大小罐且当前 1 点时可用 2 大罐补至 21 点。库存不足时尽力补充可支持下一局的合法组合。组曲以完整三首为最小单位，组内不补充；校准和被动一键只计算各自实际需要的一首。无单任务累计补充上限，不使用星石或其他道具。库存、数量、预览、二次确认、成功提示和主页体力读回均连续稳定复核；不明消费保留未决记录，新任务、新 MFA 会话均不能绕过。

演出开始后不读取体力界面、不打开补充窗口。协力、竞演只使用主页凭据，在每次尝试前保守预扣；失败不猜测退款。只有完整演出、触点清理及既有结算导航完成后，预计不足下一局时才回主页补充并重新入房，可能换房；无法确认安全回主页边界时警告并跳过本次补充，继续原演出流程。自然结算回到主页时也会刷新体力，补充耗时不占用随后进入演出的导航预算。单人和自动沿原每局回主页路径检查，单人排练不预补普通体力。校准仅为正式验证预留一首；被动一键仅从主页启动时补充，已有开场封面或现场则跳过，不离开现场。组曲第 2/3 曲续跑不强制回主页，完整三首结算后才开始下一组的主页补充。挑战使用独立点数，不显示普通体力补充选项。

体力识别失败、库存不足或未决消费不会终止整项任务：保存诊断、警告并安全取消或关闭补充窗口，恢复主页后继续；消费结果不明仍保留保护，禁止重复消费。未知体力账本不强制反复回主页，也不拒绝下一局。识别失败的窗口截图、模板分数、OCR 原文与置信度保存在 `debug/stamina-refill-diagnostics/`，不依赖演奏 Trace 开关；必要导航恢复仍无法安全继续时保留明确原因。

大小火罐实际 +1 / +10、库存变化、成功提示及关闭后读回有受限实测记录；结合剩余次数的批次补充已在本次竞演中实测；其他模式和批次组合仍待覆盖。本地 `debug/stamina-refill/` 保存消费审计与未决保护，不能删除未决记录后自动重试。进入“道具”选择页会检查页面实际送达，仅在仍处于已确认的道具/星石选择窗时有界重试；页面未送达与数字读取失败分别记录。

各实时任务的“诊断记录”可选择“开场截图＋轻量 Trace”：保留本局已有的准备、准备按钮、黑场、最终封面和首音门禁画面，首音后 20 秒内继续有界采样，然后仅继续 Trace。PNG 截图与 `opening_frames.jsonl` 索引保存在该局 `debug/recordings/` 证据包中；关键阶段首帧、首个门控观察帧和关键判定事件优先保留，开场缓存最多 128 张，记录观察时刻、可用截图请求/返回上界元数据、阶段、首音相对时间、容量和丢弃状态。整局的掉血和判定事件截图使用独立的有界缓存，超限时明确记录缺图原因，不引用未保存的图片。门控首帧不等于实际基线建立帧。关键启动期只缓存真实帧，结束或失败清理后再后台编码存盘，不生成视频或补位帧；重复旧帧不会冒充新截图。Native 握手等待期间沿用既有框架刷新路径，正式演奏期间复用引擎截图。截图采样与未覆盖间隙不能作为全程连续证据，失败只警告并继续任务。轻量 Trace 保留引擎阶段、生命、动作和耗时；主页体力补充另有独立诊断。原有关闭、轻量 Trace 和完整录像选择保持独立，已选的开场选项直接改用截图，无需重设。

协力与竞演的选曲输入在框架点击前重新确认当前选曲页；页面已进入准备阶段时，先完成本局难度、Profile 和演出表现检查，再点击准备。入房至准备页的早期证据按尝试独立缓存，记录页面匹配分数、坐标和采集时间，清理后再后台保存；即使尚未进入实时引擎，也能留下失败末帧，不借用上一局的身份或完成凭据。轻量 Trace 留低频状态和末帧，开场截图及完整记录额外保留有界阶段截图；取证异常只警告并继续任务。

## 🚀 快速开始

### 普通用户

1. 前往 [Releases](https://github.com/coatcn1/MaaBanGDream/releases) 下载最新的 `MaaBanGDream-v*-win-x64.zip`。
2. **完整解压**，双击 `启动 MaaBanGDream.cmd`。
3. 连接 Android 设备或模拟器，设置为 **1280 × 720、DPI 240**。
4. 实时演奏前按[使用指南](docs/usage.md)配置游戏、校准并选择匹配的 Profile，再添加任务运行。

定制 MFA 默认核验所选雷电的 Windows ADB 端口进程归属；同端口冲突时仅选择可证明归属的地址，
身份不明则拒绝连接。保存的设备序列号保持不变。
MuMu 与雷电双开后连接失效时，可在任务停止后重新连接或刷新设备；已验证路由变化时会重建连接及截图上下文。
任务执行期间不允许手动重连，避免打断正在进行的输入。

> [!IMPORTANT]
> Windows 便携包已经包含定制 MFAAvalonia、MaaFramework、本地谱面、Agent、便携 Python 与 .NET 运行时。<br>
> 普通用户不需要额外安装 Python、Miniconda、.NET 或开发工具。

> [!NOTE]
> 首次启动会在解压目录内展开便携 Python，因此可能比之后稍慢。

程序更新使用 MFA 的 GitHub 更新入口，保留配置、Profile、日志、调试记录和谱面；谱面单独同步。
主分支可能包含尚未发布的修改，随包版本说明见 `resource/Release.md`，近期改动见 [CHANGELOG](CHANGELOG.md)。

演出设置通过 UTF-8 管道读取和保存，兼容旧 Profile 中的中文及特殊字符；加载失败时不自动保存默认值，调用和自动保存错误会写入日志。原 Profile 与 `selection.json` 无需删除、转换或重新校准；隔离包已验证旧 Profile 升级保留及设置后端保存重开，正式客户端界面仍待验收。
Special 只有确认不可选时才允许显式回退 Expert；实时校准要求精确选择 Special。
实际 Special 缺少可信本地谱面时，不发送演奏触控。

最终封面从第一张有效画面读取并保存实读标题；标题切换为目标得分时，沿用同一封面此前的歌名。
最终封面默认读取完整标题条，避免长标题两端被截断；额外宽框补全与协力准备超时恢复仍为默认关闭的开发候选。
标题匹配容忍同音平片假名混读，长短同前缀标题用完整文字复核歧义；目标得分页保留颜色与数字布局检查并补偿淡入亮度。这些从 [PR #87](https://github.com/coatcn1/MaaBanGDream/pull/87) 拆分吸收的调整目前仅完成离线验证，仍待真机验收。
协力准备页也保留完整标题裁切。《わちゃ・もちゃ・ぺったん行進曲》Expert 已在额外宽框候选关闭时完成单人完整演奏验收；协力房间、其他曲目和难度仍待验收。确认失败时，即使关闭普通录像，也保存决策原图和标题判定记录。
完整曲库唯一封面、标题一致且展示等级差不超过 1 级时允许确认；共享封面、标题冲突或更大差异仍保留保护。
具体任务规则、失败重试与模式验收范围见[使用指南](docs/usage.md)。

### 组曲演奏

自由巡演可用当前曲目或每首随机；课题巡演沿用游戏预设三曲和难度。
次数按歌曲计算，有限次数为 **3–999 且是 3 的倍数**，填 **0** 则无限循环完整三首。
每曲在自己的准备页确认身份，必要时由最终封面补全；三曲 Profile 流速须一致，第三曲后按曲序保存结果。
断点续跑、完整三首重试和成绩缺失处理见[组曲说明](docs/usage.md#组曲)。

> [!TIP]
> 有谱面时读取已校验的**本地谱面**，演奏过程中不联网下载。定时或手动同步只在全部实例没有执行或排队任务时联网。

## ⚙️ 谱面同步

进入 `设置 → 谱面更新`，可查看清单、手动同步或设置定时增量更新。
自动更新默认每 **24 小时**检查，可关闭或设为 **1–720 小时**；失败至少退避 15 分钟，失败或中断保留旧资源。
关闭自动更新不影响手动同步；同音符数的远端谱面修订无法仅靠索引检查发现。

“关于我们 → 清理缓存”清理诊断文件，保留配置、Profile 和谱面；任务或谱面维护期间拒绝清理，并显示实际释放量与残留原因。

详细说明：[📘 Bestdori 本地谱面仓库说明](docs/bestdori-chart-repository.md)。
