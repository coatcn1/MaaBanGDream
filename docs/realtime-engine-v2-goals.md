# 实时演奏引擎 V2 目标（C++ Native 基线）

> 本文件定义 Native V2 的实现边界和验收标准。此前 Python Legacy 引擎的真机
> 成绩是对照证据，不代表 Native 已交付。Native 目前仍是未发布、默认关闭的
> 实验路径，最终成绩必须由用户在真实设备环境验收。

## 当前方向

现有 C++ 谱面解析、动作编译、绑定、minitouch 客户端和测试框架继续保留，不再
回到 Python 逐音符定时，也暂不开发新的 Android 执行器。当前路径是：

```text
音乐开始前 prearm
        |
        v
光闸给出开演锚点
        |
        v
C++ 以绝对谱面时间滚动发布 500 ms 前瞻块
        |
        +-- 队列低于 200 ms 时补块
        +-- 设备待执行队列不超过 750 ms
        +-- 已执行 jlog 仅修正尚未发送的块
        |
        v
drain/finish 或 cancel -> 统一 report
```

Python 只保留页面导航、演出前门禁、歌曲与谱面确认、开演锚点、约 5 Hz 的生命/
终态监控和结果解析。Native 从第一个音符开始独占输入；故障时安全终止，禁止一次
演奏中混用 Native/Legacy 或中途回退造成双重触控。

## 正确性基线

- TAP 50 ms、FLICK 80 ms、Slide 每 10 ms 插值，验收期间参数锁定；
- 每个 HOLD 必须移动到最终尾点；尾部 FLICK 复用活跃触点执行 `MOVE -> UP`；
- 同时音符的 DOWN/MOVE 先写入，再由同一 commit 提交，不能被单个 TAP 等待串行化；
- 触点状态机必须拒绝重复 DOWN、悬空 MOVE/UP 和泄漏；停止、异常、歌曲终态均
  释放全部触点；
- 动作执行证据必须通过完整 minitouch 命令 FIFO 和 commit 回执闭环。缺失、额外、
  乱序或日志环形缓冲区溢出都必须明确失败，不能用计划时间冒充执行时间；
- 正常完成要求 `planned == sent == executed`、证据完整且分块下溢为零；
- 启动探测与正式 jlog 分开统计。时钟映射记录偏移和不确定度；不确定度大于
  1 ms 时，绝对漂移指标无效，不能据此宣称通过时序门槛。

正式验收期间使用同一个冻结 Profile 偏移，关闭自动时延学习，避免控制器振荡
掩盖引擎缺陷。环境签名必须精确包含分辨率、DPI、帧率、画质和音符流速。

## 可观测性

每轮必须有唯一 run ID，并关联游戏结果、Native 报告和原始 jlog。报告至少输出：

- 计划、发送、执行动作数，各类手势数量及和弦组数；
- 分块数、最大队列深度、下溢次数；
- 主机/设备时钟偏移、映射依据、不确定度；
- 有效漂移样本数及 P50/P95/最大值；
- 停止释放延迟、设备端 PID 释放是否确认、观察证据是否完整；
- 游戏终止原因和传输终止原因。

开演前空闲和探测日志单独记录，不得计入设备执行延迟。结果日志不能只展示 Python
触发次数，也不能在证据不足时把正常 drain 推断为成功。
完整性门禁要求后端与 C++ 会话终态均为 `finished`，且不存在发布、设备、回读或释放
错误；准备线程超过时限仍未退出时必须失败，不能让迟到连接进入下一局。

## 离线门禁

上真机前按顺序完成：

1. C++ 动作语义、触点状态机、滚动会话、jlog 解析与时钟校准测试；
2. Native Python 绑定、prearm、独占输入、报告完整性和异常取消测试；
3. 离线 `trace.jsonl` 重放与完整 `scripts/verify.ps1`；
4. 独立虚拟 minitouch 在空闲和 CPU 压力下各运行 120 秒：零分块下溢、绝对
   时延 P95 不超过 3 ms、最大值不超过 8 ms、取消释放不超过 500 ms。

虚拟设备测试只证明主机侧调度、协议、队列和取消路径，不代表 Android、模拟器、
ADB 转发或真实 minitouch 的端到端成绩。如果 120 秒门禁在队列不超过 750 ms 的
前提下不能通过，应停止继续堆叠补偿参数，转而评估独立的 Android 绝对时钟执行器。

### 2026-09-03 本地离线结果

- C++ 构建与单元测试：1685 项通过；
- Python 与仓库完整验证：800 项通过、7 项按环境跳过；固定 MFA 运行时兼容检查通过；
- 两份既有非空 `trace.jsonl` 重放正常退出，其中完整长记录结束时无残留触点，
  中断短记录由清理阶段释放 3 个触点；
- 虚拟 minitouch 空闲和 CPU 压力各 120 秒均完成 399 块、
  `planned = sent = executed = 2944`、零下溢、零协议错误、最大队列 500 ms；
- 空闲漂移 P95/最大值为 0.086/0.838 ms，压力为 0.052/0.440 ms，取消释放约
  1.5 ms，均通过本节门槛。

因此当前不触发 Android 执行器升级条件。上述结果仍是虚拟设备证据，Native 保持
默认关闭，必须完成下节用户真机门槛后才能宣称演奏目标达成。

## 真机验收

第一里程碑固定为同一首 Expert 谱面。先运行不计入验收的偏移调优局，再冻结歌曲、
难度、流速、Profile、视觉设置和 Native 偏移，连续运行 10 局：

- 每局 `Great <= 5`；
- 每局 `Good = Bad = Miss = 0`；
- 任一局失败即保留对应 run ID、结果 JSON、Native report 和原始 jlog，并返回动作
  语义、调度、传输、设备执行或结果解析的对应层排查。

第一里程碑通过后，再验证稳定 AP：20 局中至少 18 局 All Perfect，其余每局不超过
2 Great，且所有 20 局始终 `Good = Bad = Miss = 0`。

除非 120 秒门禁明确失败并触发升级条件，否则不开发新的 Android 执行器。在第二
里程碑完成前，不扩展随机歌曲、逐曲自适应或视觉谱面规划，也不推送、合并或发布
Native 路径。Legacy 继续保留为单独可选回退，但不得作为 Native 真机验收结果的
一部分。
