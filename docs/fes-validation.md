# Fes 候选验收边界

PR #64 的安全修正先在独立分支完成。2026-09-29 活动已关闭，当前不能进行真实房间验收。
自动测试与合成帧复现不能证明真实首音、房间导航或连续演奏稳定，候选不得据此合并或发布。

## 已收紧的边界

- 首音门控拒绝预算耗尽时明确失败并清理输入，不得改用无证据的直接触发。
- 逐曲 `song_timing_overrides` 缺省为空，仅用于 Fes 正式 Native；不影响 Legacy、其他模式或校准。
- 只有完整 run ID 与 Fes 模式一致的本局终态报告才能支持瞬时引擎失败重试。
  导航、未知失败、Profile/身份/谱面/流速冲突、门控预算耗尽、生命归零及停止均不重试。
- 已完成的演出或触点清理失败不重演；每局成功后才重置重试预算。未知页面恢复最多重启游戏一次。
- 跳车信号只在本局演奏回调后消费，旧局信号不能让导航异常发送 HOME。

## 活动开放后的验收

1. 独立部署开发候选，保留已验收版本及 Profile，确认没有另一自动化程序控制设备。
2. 自动匹配至少覆盖一次正常 loading 和一次漏过 loading、由演奏场确认交棒的流程。
   检查请求/实际难度、Profile、最终封面、实际标题和谱面一致，首音确认前无演奏触控。
3. 分别覆盖单音、双押、静止长条与横跨多轨长滑条首音；保存首音前后实际帧、
   `photogate_events`、首音锚点和设备输入回执。拒绝转场假闪，不能用合成帧代替这一项。
4. 完成至少两首不同歌曲的连续多局，核对次数、成绩、回主页重新匹配和逐局 run ID。
   验证无逐曲覆盖与有已标定覆盖两种情况，不沿用贡献者未经独立复核的常数。
5. 注入一次可分类瞬时失败，确认按预算释放输入、恢复主页并建立新局；
   身份/Profile/流速硬冲突、未知失败与预算耗尽不得自动重试。
6. 验证生命归零停手、Native 本轮 reset 回执、HOME 后不自动重开游戏、Finalize 不破坏后台现场；
   同时验证准备、门控和演奏中用户停止时不继续 HOME、截图、恢复或记录业务失败。
7. 回归普通单人、协力和校准，确认 Fes 偏移与门控没有改变既有模式。

## 交付状态

本候选只做源码和离线验证，不覆盖开发 MFA 或正式安装。用户已授权将修正追加提交并
推送到 PR #64 的贡献者原分支 `feature/fes-live`，PR 保持草稿，不合并、不发布。
活动开放后需重新确认当前游戏界面与候选源码版本，再完成以上验收。

回退安全修正时在同一分支追加 Revert，不强制推送或改写贡献者历史。
