# 实时演奏 Profile v1

实时演奏对设备与游戏环境高度敏感。Profile 不是普通偏好设置，而是一次校准结果与运行环境的绑定凭据。

## 环境签名

以下字段必须全部与校准时一致：

- 分辨率；
- DPI；
- 游戏帧率；
- 演出画质；
- 音符流速；
- 按键类型；
- 点击特效；
- 判定辅助状态。

任意字段变化都会拒绝加载 Profile，要求重新校准。旧 Profile 缺少视觉字段时迁移为历史默认值 `TYPE1 / TAP EFFECT 1 / 判定辅助开启`。首阶段仍以 `1280×720 / DPI 240 / 60 FPS / standard / 2.0` 为目标环境，但实现不把这些值当作永久常量。

`视觉设置评估（实验）`可以临时复用已验收 Profile 的几何和偏移参数，但只忽略三项视觉字段。实验结果会标记为 `visual-evaluation`，不能验收或覆盖正式 Profile，也不计入正式成功率。确定最终视觉组合后必须重新执行正常校准。

## 本机数据与验收

运行生成的文件保存在 `profiles/*.json`，该路径已被 Git 忽略。程序只接受此目录内的相对 JSON 文件，防止读取任意本机路径。

新 Profile 默认应为 `accepted: false`。只有用户完成真机验收并明确确认后，后续校准流程才可以将其标记为 `true`。仓库中的 `docs/realtime-profile-v1.example.json` 仅展示格式，不能用于正式实时演奏。

## 当前接入状态

MaaController 取帧、音符观察、30 秒机器人排练和 Easy 真机验收已经完成。Profile 草稿从实际截图确认 1280×720，并使用本机锁定的 DPI、游戏帧率、画质与音符速度形成环境签名；只有原子验收后的最新匹配 Profile 可以驱动触控。

下一步是完成整首排练并解析结算 FAST/SLOW 数据，在用户再次确认后调整 `timing_offset_ms`。
