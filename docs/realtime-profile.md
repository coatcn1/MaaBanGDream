# 实时演奏 Profile v1

实时演奏对设备与游戏环境高度敏感。Profile 不是普通偏好设置，而是一次校准结果与运行环境的绑定凭据。

## 环境签名

以下字段必须全部与校准时一致：

- 分辨率；
- DPI；
- 游戏帧率；
- 演出画质；
- 音符流速；
- 实时演奏引擎。

任意有效字段变化都会拒绝加载 Profile，要求重新校准。旧 Profile 中的
`note_skin_type`、`tap_effect`、`judgement_assist_effect` 仍会读取以兼容版本 1 格式，
但不参与匹配；缺少时按 `TYPE1 / TAP EFFECT 4 / 判定辅助关闭` 补齐。

旧校准会话续跑使用同一套兼容规则：视觉字段变化不会阻止读取或续跑，分辨率、DPI、帧率、画质、流速和引擎仍保持严格匹配。

## 校准与正式演奏

实时校准完成一首排练和一首正式验证。排练取得候选偏移，正式验证检查整首完成、
存活和结算结果，并要求 MISS 小于 10；通过后接受候选 Profile，并启用到对应难度。
生命归零或正式验证未通过时保留未接受草稿，不能用于正式实时演奏。

正式演奏前检查 `accepted: true`、难度兼容性和六项环境字段；本局首音锚点与
Profile 偏移在启动 Native 前冻结，不把本局
FAST/SLOW 直接写回长期 Profile。切换 Native/Legacy 后须使用匹配引擎的 Profile。

操作入口与流速设置见 [使用指南](usage.md)。

## 本机数据

运行生成的文件保存在 `profiles/*.json`，该路径已被 Git 忽略。程序只接受此目录内的相对 JSON 文件，防止读取任意本机路径。

新 Profile 草稿为 `accepted: false`，不能手工修改标记来绕过正式验证。
仓库中的 `docs/realtime-profile-v1.example.json` 仅展示格式，不能用于正式实时演奏。

## Native 本局实验反馈

“演出设置 → Native”的判定反馈微调与等待抖动过滤均默认关闭并持久保存。首次准备冻结本局选择，同局重建沿用快照，关闭 Native 保留选择；原有 `native_life_feedback_enabled` 配置键继续兼容。

判定反馈微调仅用于 Native 正式演奏开始后的有效演奏场，不依赖生命值或掉血次数。每 3 秒开启 0.8 秒窗口，以 20Hz 采样；平时截图、生命和终点监视约 5Hz，窗口结束额外复核一次场景。每窗最多一张可信方向票，12 秒内三个可信同向窗口建立趋势，才请求 FAST 延后 2ms / SLOW 提前 2ms；持续字样可跨独立窗口投票，同一窗口不会重复请求。

新帧必须序号严格递增、未复用且请求年龄不超过 80ms；窗口内采样断档、混合方向、可信反向或场景失效会取消趋势，反向当帧撤销尚未应用的旧请求。空窗仅保留尚在 12 秒有效期内的证据，不请求或延续请求 TTL；方向票按实际判定时间逐张过期。输入不合格区间只跳过并打断去抖，保留本窗已有可信证据；窗口结束重新检查近期输入资格。

接受请求只表示等待安全空档，不清除趋势，也不会重复提交。过期或拒绝后，下一可信同向窗口可以重试；确认已应用后，须取得首个受影响切片的效果边界，以及该切片中最近 TAP / FLICK 的实际执行来源，才按新截图续调。截图请求必须晚于该输入执行，避免预取旧图借用新回执。每窗最多一次请求，间隔至少 3 秒；相位上限只在真实反向应用释放余量后解除，停止等终态不无限重试。

统计分别记录实际采样、去抖报告、方向票、请求、接受及 backend 应用。不可变状态快照关联本局、请求序号、状态游标和效果边界；等待触点边界或安全空档只在状态变化时记录，接受请求不等于已经改善游戏判定。

实际调整仍只作用于未来未编译输入的安全空档，保留触点释放、执行回执、时钟不确定度与本局累计 ±40ms 护栏。首音锚点、Profile timing offset 与设备等待成本残差保持独立，排练、校准和 Legacy 沿用原反馈。旧等待抖动环境变量不再覆盖保存值。既有正常挑战验收未触发实际相位应用；近期协力已出现小步应用，但实机效果不足，本次续调机制仍待专项真机复验。

首音证据独立于调试和微调开关，在触发时缓存真实前后两帧 ROI，并由共享有界后台队列保存到 `debug/recordings/`。小 JSON 保留截图时序、复用标记、颜色均值及前前帧参考、变化分数、阈值插值、稳定与宽限状态、固定延迟、冻结 Profile 偏移、探针首读成本和最终锚点。Native 结果的 `start_evidence` 区分 queued / written / failed / queue-full；路径存在于报告不代表已经写成。诊断不增加截图、不等待停止，不改变门控判断或锚点计算。
